# Artifact: Information Security Policy Hierarchy

**Purpose:** Clarify document types so security expectations are enforceable, measurable, and operational.

| Document type | Purpose | Characteristics | Typical approval |
|---------------|---------|-----------------|------------------|
| **Policy** | High-level management intent and mandatory expectations for protecting information assets | Broad, principle-based; defines *what* and *why* | Board / CEO / CISO / Steering Committee |
| **Standard** | Mandatory minimum requirements that make policies measurable | Specific, quantifiable; may reference technologies | CISO / IT Director / Steering Committee |
| **Guideline** | Recommended good practice (not mandatory) | Advisory and flexible | Security team / department managers |
| **Procedure** | Step-by-step instructions for how to implement standards/policies | Action-oriented, sequential; defines *how* | Process owner (e.g., IT Operations) |

## Classification examples

| Statement | Classification | Why |
|-----------|----------------|-----|
| All employees must use MFA when accessing the corporate network remotely. | Policy | Organization-wide mandatory requirement |
| To configure MFA, install the authenticator app, scan the QR code, and enter the 6-digit code. | Procedure | Step-by-step operational instruction |
| Developers should prefer parameterized queries to reduce SQL injection risk. | Guideline | Recommended practice, not a hard mandate |
| Passwords must be at least 12 characters and checked against breached-password lists. | Standard | Measurable minimum control requirement |

## Why this matters

Without hierarchy discipline, organizations mix aspirations with instructions — making audits harder, ownership unclear, and enforcement inconsistent.
